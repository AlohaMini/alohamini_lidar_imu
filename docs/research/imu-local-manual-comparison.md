## 1. 必须修正的差异

| 项目 | 此前依据网上资料的判断 | 本地资料核实结果 | 对方案的影响 |
|---|---|---|---|
| USB 转串口 | CP2102 | CH340X，Type-C 接口 [D1，第 4 页] | 按实机 VID/PID、序列号或物理端口绑定，不套用旧 USB 规则 |
| 默认通信 | 9600 bps、10 Hz | 产品与协议一致写 115200 bps、100 Hz [D1，第 6 页；D3，§6.4] | 以 115200／100 Hz 为接入基线，仍需读回实际配置 |
| 支持速率 | 0.2～200 Hz | 协议列 1～250 Hz；115200 限制到最高 125 Hz，230400 及以上才允许 250 Hz [D3，§4.5.6] | 初期 100 Hz 足够，不直接提高至 250 Hz |
| ROS 版本与包 | Ubuntu 20.04／Foxy，`wit_ros2_imu` | Ubuntu 22.04／Humble，`imu_usb`、`imu_iic` [D4，第 17～19 页] | 优先修整本地 USB 包，已有 Humble 接入基础 |
| 主动上报帧 | WIT：`55 51/52/53/54`，固定 11 字节 | Hiwonder：`55 55 ID LEN DATA SUM`，变长 [D3，§3.1] | 完全不同的解析方式，禁止沿用旧 WIT 解析器 |
| 原始运动数据 | 固定 ±16g、±2000°/s 换算 | `0x03` 同时承载加速度、角速度和陀螺仪温度；按当前量程换算 [D3，§3.2.3] | 必须读取／确认量程，不能固定旧比例 |
| 示例单位与参数 | 旧附件重复换算、端口硬编码、无协方差 | 本地 USB ROS 2 代码正确分两步换算到 SI，支持参数和协方差 | 撤回把旧示例缺陷归到当前本地驱动的推断 |
| 陀螺仪标定 | 旧手册描述运行中的静止阈值／稳定时间 | 本地协议定义上电自动校准；树莓派教程要求先标定保存，launch 默认关闭自动校准 [D3，§4.3；D4，第 1 页] | 启动校准与正常运行分阶段，不能假定旧固件的持续自动调零机制 |
| 姿态轴向 | 旧手册描述 Y 朝前／指北及 ENU | 本地文档说明 Roll/Pitch/Yaw 与 q0～q3，但未充分定义姿态世界参考系 | 不沿用旧坐标结论；实测轴向和正负号后设置外参 |

## 2. 已确认的数据格式

主动上报是 `55 55 ID N DATA SUM`，总长为 `N + 5`；配置及配置响应是
`55 AF ID N DATA SUM`。多字节数值为小端，校验为校验字节之前所有字节累加取低 8 位。[D3，§2～4]

| ID | DATA 长度 | 内容 |
|---|---|---|
| `0x01` | 6 字节 | Roll/Pitch/Yaw，`int16 × 180 / 32768`，单位度 |
| `0x02` | 8 字节 | q0～q3，分别为 `int16 / 32768`；本地驱动映射为 ROS w/x/y/z |
| `0x03` | 14 字节 | 加速度三轴、角速度三轴、陀螺仪温度；前六项为原始 LSB |
| `0x04` | 6 字节 | 磁力计三轴原始 LSB |
| `0x05` | 10 字节 | 气压 Pa、相对高度 cm、气压计温度 |

默认加速度量程 4G，对应 8192 LSB/g；默认陀螺仪量程 1024 dps，对应 32 LSB/(°/s)。
因此在**确认默认量程生效时**：

```text
acc_m_s2 = acc_raw / 8192 × 9.80665
gyro_rad_s = gyro_raw / 32 × π / 180
```

默认加速度带宽 48.3 Hz、陀螺仪带宽 32.6 Hz，不是此前所述 20 Hz。[D1，第 6 页]
`0x03` 帧没有采样时间戳或序列号字段，本阶段只能记录主机收到新帧的时间并评估传输延迟，
不能把 ROS 循环频率当成真实采样频率。[D3，§3.2.3]

## 3. 本地资料内部也有出入

1. **速率描述冲突。** 上位机教程第 10 页写“默认 125 Hz、0.2～200 Hz、每包 11 字节”，
   产品简介默认表、协议频率编码表和本地 launch 则分别支持“默认 100 Hz、1～250 Hz、变长帧”。
   已查看 PDF 原页确认并非文字提取错误。实施以协议、代码交叉验证并读回实机为准，不能用上位机截图的选中值认定出厂配置。
2. **示例校验和有误。** 按协议自己的累加规则及源码生成函数离线计算如下，未向设备发送命令：

   | 协议示例 | PDF 中的最后一个字节 | 按帧内容计算的校验字节 |
   |---|---|---|
   | §6.2、第 16 页：`55 AF 04 01 01`（4G） | `8C` | `0A` |
   | §6.2、第 16 页：`55 AF 03 01 02`（1024 dps） | `8B` | `0A` |
   | §4.4.2、第 9 页：`55 AF 01 01 00`（陀螺仪校准） | `86` | `06` |

   配置帧应由代码按规则生成，不能直接抄错的十六进制示例。§3.2 的逐帧简表还省略了第二个帧头和长度字段，完整格式应以 §3.1 与解析代码为准。
3. **默认值具有层级。** 出厂／复位默认开启上电自动校准；配套 launch 默认关闭；直接运行节点时其缺省参数又为开启。
   项目必须由统一 launch 显式传参。`publish_tf` 则默认开启，接入机器人时必须显式关闭。[D1、D4、源码核对]
4. **保存与生效不同。** `SAVE` 才使配置掉电保存，波特率保存后还需按教程重新上电；`RESET` 只恢复运行配置，不等于重启。[D2，第 8 页；D3，§4.4]

## 4. 更新后的接入决策

- 复用本地 `imu_usb` 的协议、量程处理和 Humble 参数接口，在项目中补齐导航所需行为；没有必要从旧 `wit_ros2_imu` 重新适配。
- 使用 `device_type=10axis`、115200、100 Hz、4G、1024 dps 作为初始参数；模块内部姿态算法按本地教程为 `9axis`。EKF 第一版仍只选 `wz`，因此模块内部使用磁力计并不意味着导航也采纳磁航向。
- 设置 `publish_tf=false`。机器人 URDF 发布 `base_link → imu_link` 固定安装关系，EKF 发布 `odom → base_footprint`。不要将驱动的动态姿态 TF 改名成 `base_link → imu_link`。
- 必须用新收到且通过校验的 `0x03` 帧触发发布，带接收时间和过期判断。当前样例即使没有新运动帧也会用 `now()` 重发缓存，可能使 EKF 持续信任旧转速；在修复前不能只凭 `ros2 topic hz` 判断传感器正常。
- 检查配置响应与实际读回值，尤其是量程；缺少有效姿态时将其协方差首项标为 -1。示例协方差是初值，需要实测标定。
- 按本地教程完成校准并保存，正常导航显式关闭启动时手动校准；若需要上电自动校准，确保车辆静止至少 2～3 秒并检查完成状态，再允许导航。标定期间会暂停主动上报。[D2，第 17～18 页；D4，第 1 页]

后续实物验证仍需确定：板卡/固件确与资料匹配、实际量程及输出频率、轴向正负、时间延迟、协方差与静止漂移。没有这些实测结果，不承诺定位精度。
